# 102 card-geometry-from-the-game-rects
epic: none · pr: none

## Decisions
- @cards @geometry — A card's interior is positioned as percentages of its own root, transcribed from the game's RectTransforms, and its type sizes are container-query width units of that root. The game lays every card out by anchor fractions of one root rect, so any unit that is not a fraction of that root has to be re-derived per card size and drifts from the source the moment either changes. REJECTED: keeping hand-tuned pixel offsets per element — they encode one card size, and the numbers have no traceable origin, so the next size change re-tunes all of them by eye. REJECTED: `rem`-based sizing — it tracks the document's root font size, which has nothing to do with how wide the card is.
- @cards @geometry — A card's box belongs to its grid slot: the slot carries the pixel width and derives its height from the card's aspect ratio, and the card fills it. A card that carries its own pixel size makes the slot and the card two sources for one number, and they disagree the first time either is edited. REJECTED: the card keeping its width and the slot measuring it — the grid needs the height before any card renders, to reserve the document height that scroll restoration replays against.
- @cards @responsive — Mobile sizing shrinks the slot; it does not transform the card. A `scale()` wrapper leaves the card laid out at its desktop pixel size and only paints it smaller, so every measurement inside it — text fitting included — answers for a size the user is not looking at, and the wrapper has to carry the unscaled box as well. REJECTED: keeping the transform wrapper for cards — it is what forced every card to know its own pixel height in the first place.
- @cards @geometry — The identity card's text follows the formation slot prefab `PersonalityFormationSlot_<Sinner>` (a 305 x 450 grid cell), while its frame, portrait, mask, grade and icon rects keep following the scroll-list item `PersonalitySwitchableSlot` (310 x 450). The formation slot is the card the user reads the game's text placement off, and its text tree differs from the list item's: a `[Rect]Level` node holds the level 3.4u above the name, and the two name nodes carry their own character and line spacing. REJECTED: moving the whole card to the 305u root — the non-text rects were transcribed from the list item and re-deriving them buys nothing the user can see. REJECTED: keeping the list item for the text as well — its name box stops 1.4 percent of the card short of where the game draws it, and it has no node for the level's lift, which the last pass had to supply as an unexplained measured constant.
- @cards @text — One node draws both of the identity slot's name segments, and it takes `[Text]GroupUpperName`'s character spacing (-2) rather than `[Text]GroupName`'s (-5). The upper name is the segment that wraps, so its tracking is the one that decides where a name breaks. REJECTED: two nodes, one per segment — the game splits a name across them by a marker the shipped i18n strings do not carry, so the split would have to be guessed. REJECTED: `[Text]GroupName`'s -5 — it narrows every line by three hundredths of an em per character and moves breaks the game does not move.
- @cards @text @i18n — The name's line pitch is the display face's own line height plus the language's entry in `TextSizeCheckerByTextLine._fontLineCorrection`, not either name node's `m_lineSpacing`. That component runs on the card and overwrites the node's spacing with the per-language correction, so the node's value never reaches the layout and one pitch cannot serve four faces whose line heights differ by half an em. REJECTED: a single browser-measured pitch for every language — it was read off one language's rendered card and put the other three's lines up to a point of card height apart from the game's.

## Superseded
- @cards @geometry → 109 — Card aspect ratios live as an expression over the game's root dimensions in the layout constants and nowhere else. REJECTED: a decimal literal per card — it hides which two numbers it came from, and nothing then catches a transcription error.

## Takeaway
- takeaway: transcribe a layout in the source's own units and let one element own the size; a conversion done once at the boundary beats a conversion repeated at every element.
