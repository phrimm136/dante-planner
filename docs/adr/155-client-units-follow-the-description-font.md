# 155 client-units-follow-the-description-font
epic: none · pr: none · supersedes: 154 @importance @stripe, 153 @coin

## Decisions
- @skill @importance — Client UI units map to page length through the description font: the unit information panels set their description TextMeshPro to fontSize 40 with auto-size off, so 40 client units are one text-sm em (0.875 rem), for every client-sized element. The importance triangle is its prefab rect, 200 units square, placed in the importance group, which carries the caution bands and overhangs the client panel (15 units for skills, 40 for passives); our decorated box is that group, so the triangle sits 37 units below the box top: a skill's 86 units in from the right edge (the `ImportanceUI` unlock position, −86/−37), a passive's at the right edge (0/−37). REJECTED: measuring the offset from the client panel — the triangle rose into the top band and, on passives, out of the box. REJECTED: fractions of the box width — the client panel's width is fixed in text units (the triangle is 15 % of the skill tab and 22 % of the skill summary popup, both at fontSize 40), so a width fraction only agrees with the game at one card width and doubled the triangle on desktop; REJECTED: 50 units to a 1.25 rem line — calibrated from coin captures rather than read from the prefab, it drew every client length 1.14 times too large.
  INVARIANT: every client-unit length (triangle, coin, plate glow, caution band and texture copy) derives from the one description-font scale — theme constants and the importance table tests.
  NON-GOAL: choosing between `ImportanceUI`'s base, part-icon and unlock positions per skill; its selection logic is not in the decompiled store.
- @skill @coin — The coin row above a skill's name draws each coin 65 units square, overlapping its neighbour by 10: the skill panel's coin layout gives every coin a preferred width of 65 at spacing −10, and the square sprite keeps its aspect. REJECTED: 50 units — that is the Summary tab's small skill slot, which drew the panel's coins 23 % too small.
- @skill @stripe — Caution bands are 52.2 client units thick, inside the box at its top and bottom edges, for skills and passives, and each copy of the caution texture (six CAUTION marks) spans 1304.2 units and scrolls one copy per 10 s; a passive pads its content by one band. The client's stripe controller sets the band to 4 % of the importance group's width and forces the scroll speed to 0.1 texture copies per second, and the texture stretches once across that width; the unit information panel is 1304.2 units wide at every screen size, so band and copy are fixed lengths. REJECTED: the material's 0.025 of the group height — the controller overwrites it on start; REJECTED: fractions of our box width — our box is not the fixed-width client panel.

## Takeaway
- takeaway: read the fixed quantity from the client before calibrating against a capture; a capture shows one layout, the prefab states the rule.
