# 139 planner-floor-boundary-and-difficulty-law
epic: none · pr: none

## Decisions
- @planner @floors @boundary — Raw floor JSON crosses one parse boundary per runtime that maps a theme pack that is absent, null or the empty string to "absent", an absent gift list to an empty list, and an absent difficulty to "unset", and reports every other malformed shape (a non-object floor, a non-array or null gift list, a non-string gift, a non-integral difficulty, a non-string pack) as an `INVALID_FIELD_TYPE` violation at that field's path. Floors at or past the category's floor count pass through untouched and unreported, since they are stored on purpose (136). The seven old sites disagreed on exactly these shapes (an empty pack counted as chosen in one sequence check and as absent in another; a non-object floor was silently skipped on the server and flagged on the client), and only one mapping lets one corpus pin both runtimes.
  REJECTED: keeping the client's strict draft schema (pack and gift list required, difficulty required) — it rejected drafts the server had accepted for months, so stored content would fail to load.
  REJECTED: treating the empty string as a chosen pack — it can never resolve to a theme pack, and the client's schema already refused it.
- @planner @floors @boundary — At the draft and publish stages a boundary violation on any floor below the count is returned alone and no rule runs; at the index stage the floors that parsed are admitted beside the violations, and a rejected object floor contributes the fields that parsed on their own (a numeric id as its text) so that the server's index matches, field by field, what the stored procedure's `JSON_TABLE` extracts. A wrong shape is fixed before rules mean anything, while the index must agree with its audit oracle (039) on content that older paths stored.
  REJECTED: running the rules over the surviving floors at draft and publish — piles derived violations (missing pack, sequence) on top of the shape error.
  REJECTED: dropping a malformed floor whole at index — the procedure indexes its parsable fields, so the drift reconciler reported every such stored row on every run.
- @planner @floors @difficulty — Floors one to five may be Normal or Hard but Normal never follows a Hard floor; floors six to ten are Hard only; floors eleven to fifteen are Extreme only; floors six and up open only when floors one to five are all Hard. This is the game's rule; the shared table holds the per-floor allowed sets and the sequence rule is one named rule in the matrix, evaluated only on floors whose set allows Normal, so a Hard-only floor reports the range violation alone. The editor offers difficulties, defaults new floors and warns on a category change through the module's predicates over the same rules.
  REJECTED: the validator table alone (per-floor sets without the sequence rule) — it accepted Normal after Hard on a five-floor planner, which the game refuses.
  REJECTED: the editor's own offer logic — it offered Normal on ten- and fifteen-floor planners' first floors, where Hard is required, and defaulted new floors to Normal there.
- @planner @floors @codes — Violation codes are the server's (`FLOOR_MISSING_THEME_PACK`, `FLOOR_DUPLICATE_THEME_PACK`, `INVALID_SEQUENCE`, `VALUE_OUT_OF_RANGE`, `DUPLICATE_VALUE`, `INVALID_FIELD_TYPE`) on both runtimes, sorted by floor index then path then code, one violation per floor for a repeated gift; the client maps codes to its messages. The server's codes are the wire contract that clients already match.
  REJECTED: the client's names on both sides — renames codes clients may already branch on.
- @planner @floors @ids — Game-data reference checks (pack known, gift known, gift affordable for the pack) stay outside the floor module and run over the parsed floors when the boundary reported nothing; an unknown pack does not hide its floor's gift checks, and an unknown gift skips only its own affordability check, since the registry answers "not affordable" for a gift it does not know. They need the game-data registry, and keeping them out lets the category-change path be one admission with no extra stage.
  REJECTED: a fourth stage that skips id checks — a second axis for one caller.
- @planner @floors @rr — Refracted Railway planners are refused by the content validator, skipped by the drift reconciler and rebuilt with a floor count of zero, which keeps their non-floor index rows; floor rules are a Mirror Dungeon concern.
  REJECTED: failing the rebuild for a non-Mirror-Dungeon category — the publish listener has no retry and the keyword backfill would stop at the first such planner.

## Takeaway
- takeaway: when one rule lives in several places, the disagreements are in the shapes at the edges (empty, null, absent, wrong type), not in the rule; decide the edge mapping once and the sites collapse.
