# 016 planner-projections-and-search
epic: none · pr: none

## Decisions
- @planner_catalog @visibility @sort — The browse projection holds visible rows only, so membership *is* the visibility predicate (published, not deleted, not taken down), sorted by first-publication recency. REJECTED: a mirror projection retaining the published, deleted and taken-down columns — modelling visibility as column values rather than row presence collapses the useful index into a two-column shape and puts three near-universal predicates on every query.
- @planner_entity_filter @planner_keyword_filter @inverted-index — Content facets split into two inverted tables, integer entity ids in one and string keyword slugs in the other, each with a reverse index and a foreign key to the write-once core. REJECTED: one polymorphic filter table holding both in a string column — it coerces the large integer index into a wide string type to accommodate the small keyword set, taxing the common case for the rare one. REJECTED: a set column for keywords — not indexable, so every filter is a scan.
- @title-search @fulltext @ngram — Title search uses MySQL FULLTEXT with the ngram parser at the default token size; the backend builds the boolean query, escapes FULLTEXT operators, and ORs it against an existence check on the keyword index to preserve title-or-keyword search. REJECTED: the default word parser — it cannot tokenize CJK, and the user base is Korean. REJECTED: a suffix table for exact substring matching — over-engineering at this scale. REJECTED: `LIKE '%x%'` and set-membership functions — non-sargable full scans.
- @selected_keywords @converter — The stored keyword column becomes a display-only JSON array, with filtering moved to the keyword index, validated on write and migrated eagerly so the data is clean at rest. REJECTED: a MySQL SET column — it needs an ALTER for every new keyword and is not indexable. REJECTED: a plain text column — it works with the existing converter but diverges from how content is stored. REJECTED: a sized string column — it forces a length recomputation on each keyword addition.
- @recommended @derived-flag — The recommended flag is derived onto the browse projection for list queries, while the detail view computes it live; the moderation source and audit trail are kept. REJECTED: the flag on the counter table — a hot-write table must not carry a queried index. REJECTED: the flag on the publication table — the vote path must not write publication state.
- @index @icp @composite — The browse index leads with the sort key and carries the low-cardinality filter columns behind it as in-index residuals; the recommended index leads with the selective flag instead. REJECTED: leading with the type column — a two-value seek is worthless and it filesorts the all-types query, which is the only shape actually issued. REJECTED: omitting the residual columns — it forces a clustered-row fetch per candidate rather than an in-index filter.
- @reconciler @drift — A scheduled reconciler validates counters against child counts, projection membership, both filter tables against the live rebuild, and the derived flag against its source, emitting structured drift records without repairing anything. REJECTED: silent auto-repair — it hides the bug that produced the drift. REJECTED: asserting the invariant only in tests — the after-commit rebuild is lost on a crash between commit and listener, which is a production-only failure mode.

## Takeaway
- takeaway: a projection's index shape is decided by what membership means, not by what columns it holds. Encoding visibility as row presence rather than as flags is what leaves the index free to serve the sort, and that choice has to be made before the table exists.
