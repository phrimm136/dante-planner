# 008 causal-consistency-read-path
epic: none · pr: none

## Decisions
- @correctness @timing (taste) — Correctness paths carry no timing constants. "Has X happened" is encoded as a checkable causal condition — a GTID applied, a tombstone present, replication caught up — never as a calibrated delay. REJECTED: pin windows and delayed invalidation — an environment-calibrated delay is an assumption that rots silently as latency moves, and it fails open. Time is for performance decisions, causality for correctness decisions.
- @ryw @gtid @cookie — Author read-your-own-write is a GTID cookie gate: capture the write's GTID via `session_track_gtids=OWN_GTID`, set an HttpOnly cookie, and let gated reads run `WAIT_FOR_EXECUTED_GTID_SET(gtid, ~0.05)` on the replica — caught up serves the replica, otherwise the primary. REJECTED: a server-side session key holding the token — the causal token must travel in-band with the request it guarantees, and a server-side store is a second asynchronous channel that re-imports the very race it is meant to close, since the lookup can itself lose to replication.
- @gtid @capture — The cookie is minted only when a non-readOnly MySQL transaction commits. REJECTED: HTTP-method-gated capture — it misses the mutating GET on the OAuth callback and mints on Redis-only writes, rate-limit rejections and authorization failures that wrote nothing.
- @sse @recipients — Recipient updates carry the entity in the event and are patched into the client cache directly. REJECTED: invalidate-then-refetch — the refetch races replication, whereas a payload has nothing to race. The client is invalidate-heavy and comment creation discards its own POST response, so client-side masking alone cannot cover this.
- @replica @miss @byid — Absence on a replica is not authoritative: a byId miss re-checks the primary before returning 404. Scoped to entity-by-id dereferences only. REJECTED: treating replica absence as final — it 404s a resource the author just created and shared. REJECTED: extending the re-check to lists and searches — absence from a list is accepted eventual consistency, and a positive-but-incomplete list is invisible to miss-triggered repair anyway.
- @replica @bulkhead — The primary re-check runs on a dedicated two-to-three-connection pool. REJECTED: sharing the write pool — a flood of junk UUIDs saturates a ten-connection pool at roughly 71 requests per second, so an unauthenticated miss path could starve writes.
- @delete @tombstone — Deletes write a Redis content tombstone synchronously before the delete response, and replica-served byId positives check it. REJECTED: relying on replication lag alone — MySQL lag spikes to tens of seconds under load while Redis lag is milliseconds. The TTL is cleanup, not the correctness gate.
- @read-path @contract — The whole contract in one line: replica hit → tombstone check → serve; replica miss → primary re-check → serve or 404; author with cookie → GTID gate. The three mechanisms partition the space (my recent writes, everyone's misses, everyone's ghosts) and none subsumes another.
- @gtid @round-trip — Cross-region write cost is reduced by unioning GTIDs across a request's commits plus targeted query fixes. REJECTED: a stored procedure for the core aggregate write — it would re-encode the optimistic-lock compare-and-set and the keyword rename map in SQL, forking the exact application-side oracle the drift reconciler exists to police, to save a few hundred milliseconds on a rare action while leaving fan-out and redundant reloads untouched.

## Takeaway
- takeaway: full determinism is not on the menu, so the deliverable is a *named* residue rather than a guarantee. Here it is a deleted entity readable for milliseconds whose every interaction fails cleanly at the primary — an accepted, bounded, articulable window instead of an unexamined one.
