# 045 errors-as-values-boundary
epic: none · pr: none

## Decisions
- @errors @frontend — A failure inside a planner pipeline travels as a `Result` value carrying one discriminated failure union per pipeline; `throw` and `unknown` exist only in boundary adapters. Three incompatible failure channels (typed throws, success/errorCode records, an abort sentinel) were being converted into one another mid-pipeline, and classification fell back to sniffing message substrings. REJECTED: typed exception classes end to end — a throw's type is invisible to the compiler, so every consumer re-derives the union with `instanceof` ladders and the string sniffing comes back.
- @errors @tanstack — `Result` stops at the TanStack Query boundary: a `queryFn`/`mutationFn` throws through the single `unwrapOrThrow` adapter, which wraps the union in `PipelineError.detail`, re-narrowed per hook via generics. TanStack's cache lifecycle — retry, staleness, error boundaries, the global `onError` handlers — keys off rejection, so a `Result` returned as data is cached as fresh success. REJECTED: returning `Result` from `queryFn` — failures get served from cache, retry and error boundaries never fire. REJECTED: augmenting the global `Register` error type — one error type for every query in the app is coarser than the per-pipeline unions it would replace.
- @errors @frontend — Classifiers are pure functions from `unknown` to a union value; reactions (cache invalidation, toasts, logging) live with the consumers of the classified value. A classifier that fires cache invalidations cannot be table-tested without mocks and hides IO behind a name that promises a mapping. REJECTED: reacting inside the classifier — one hidden side effect per classification site, and the auth-cache write ran even for callers that only wanted the label.
- @types @frontend — Absence stays native: `T | null` with narrowing, no `Option` wrapper; when the absent states carry distinct meanings, the value becomes a named union instead of a nullable. A wrapper adds no safety beyond what narrowing already proves and taxes every boundary (React props, query cache, Zod, JSON). REJECTED: an `Option<T>` type for uniformity with `Result` — `Result` earns its box by carrying a reason; absence has nothing to carry.

## Takeaway
- takeaway: describing a failure, deciding what it means, and reacting to it are three jobs; a library that owns control flow (query cache, error boundary) is a boundary where value-passing must hand the failure to that library's own channel, through exactly one adapter.
