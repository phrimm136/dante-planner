# 546 an-alert-rule-carries-the-case-that-fires-it
epic: none · pr: none

## Decisions
- @alerts @data @cases — Grafana alert rules are YAML data under `deploy/grafana/rules/`, one file per rule group, and each Prometheus or Loki rule carries at least one case in which it must fire and one in which it must stay quiet. Four rules compared with a filter (`== 0`, `< 1`), which returns the value 0 at the moment the rule should fire, while the rule's threshold node fires on a value above 0; they had never been able to fire, nothing evaluated a rule before it reached Grafana, and 14 days of production history held no moment in which any of the four conditions was true, so production could not show it either. Re-check [manual]: `rg -c '^- name:' deploy/grafana/rules/cluster-rules.yaml deploy/grafana/rules/app-rules.yaml`.
  REJECTED: keeping the rules in the import scripts and linting the expression text for a `bool` comparison — a text rule cannot see a wrong selector, a renamed metric or an inverted condition, all of which leave a well-formed expression that returns nothing, and an empty result is quiet by design (`noDataState: OK`).
  REJECTED: moving to the Grafana Terraform provider first — a plan detects drift between git and Grafana, not an expression that cannot be satisfied, so the dead rules would have moved intact; the YAML stays readable by `yamldecode` when that move happens.
  REJECTED: alerting on an empty result — a deleted node and a scaled-down exporter also empty the result, so absence is owned by the staleness rules and is not evidence of a broken rule.
  INVARIANT: a Prometheus or Loki rule without a firing case and a quiet case reaches neither the test nor Grafana — the loader in `deploy/grafana/rules.py`, the only reader of the rule files, refuses it (`deploy/grafana/tests/test_rules.py`).
  NON-GOAL: CloudWatch rules carry no case — their threshold applies to the metric itself, so there is no expression to return a filtered zero.
  NON-GOAL: `deploy/grafana/create-staleness-rules.sh` keeps its own rule literals — it is run once by hand after remote-write data flows, not on merge.
- @alerts @gate — The `alerts` stage of the deploy lane evaluates every case before merge: each Prometheus expression is wrapped as `count((<expr>) > 0)` and run by `promtool test rules` on the case's synthetic series, and each Loki expression is run as an instant query against a throwaway Loki holding the case's lines. The wrap is Grafana's firing condition; without it promtool passes a filtered zero, because a Prometheus alert fires on any returned sample.
  REJECTED: evaluating the rules against production series — the lane would hold a production credential, and it would test the state of production, not the change.
  INVARIANT: the stage can detect a rule that cannot fire — it evaluates a committed fixture whose only rule is `up == 0` and fails unless that fixture's firing case fails (`.github/scripts/deploy-test.sh`, stage `alerts`).
  NON-GOAL: proving that a rule's series exist in production — the remote-write keep-list check owns the metric names, and the staleness rules own absence.
- @alerts @cases @production-shape — A firing case carries the series production always has beside the one under test, and a silence rule's window is sized from the longest benign silence. Probes and scrapes send about 3800 `/actuator` requests per cluster per 5 min (Mimir), so `traffic-drop` summed over every uri could not fall below 1 while a pod lived, and its first case passed only because it held no probe series; the rule now excludes `uri=~"/actuator.*"`, where the 14-day minimum is 41 (Oregon) and 8.75 (Seoul). `backend-log-silence` over 10 min was true in 19 five-minute slots in Seoul in 14 days and in none over 15 min or more, so its window is 20 min. `blacklist_check_skipped_total` is registered at construction, because a counter first seen above 0 gives `increase()` nothing to count. Re-check [assert]: `rg -c 'uri!~"/actuator' deploy/grafana/rules/app-rules.yaml`.
  REJECTED: keeping the 10 min window with a longer pending period — the window, not the pending period, is what a quiet night fills.
  INVARIANT: none — whether a case holds production's shape is a review question; the gate proves only that the case as written fires.

## Takeaway
- takeaway: a rule that only a query engine can interpret is tested by giving that engine an input in which the rule must fire, and the test has to apply the same firing condition the consumer applies.
