# 075 drift-audit-comparison
epic: none · pr: none

## Decisions
- @reconciler @audit @observation — An audit normalizes what it reads exactly as the runtime serves it — a corrupt keyword column compares as the empty set the converter returns — while the repair path abstains on the same input; the two readings of one column are deliberately different functions. A total read is correct for observation because the audit's subject is what users experience, and wrong for repair because acting on a guessed value destroys the evidence; sharing one parser between them makes corruption either silently hide drift or silently drive repair. REJECTED: one shared abstaining parser — a column the runtime serves as empty while its source row disagrees is real user-visible divergence, and the abstain path reduced it to an unattributed warning.
- @reconciler @audit @collation (taste) — Audit equality opts out of the display collation: scalar copies compare under `utf8mb4_0900_bin`. The columns' `utf8mb4_unicode_ci` exists for user-facing search and swallows exactly the divergences a copy audit exists to catch — case-only renames whose sync failed — and `utf8mb4_bin` is not sufficient, because it still pads: trailing-whitespace drift survives it. REJECTED: comparing under the column collation — a stale copy differing only in case reads as equal forever.
- @reconciler @audit @window — The recommended-notification audit bounds itself to latches younger than a window sitting inside both notification retention windows, and the cutoff is computed on the database clock. Absence of a witness row is evidence only at ages where the row could not have been legitimately deleted; unbounded, every latch eventually outlives both its event row and its notification and reports permanent drift, so the audit stops being decidable. A JVM-side cutoff lands hours off on any non-UTC host against a `CURRENT_TIMESTAMP(6)`-written latch. REJECTED: no lower bound — correct today only because the tables are younger than the retention windows, and wrong on a date that can be named in advance.

## Takeaway
- takeaway: a drift audit is a claim about what two readers would disagree on, so every comparison inside it must be made with the reader's own semantics — the runtime's normalization, a byte collation instead of the display one, a clock shared with the writer — or the audit measures the distance between itself and the system instead of the drift inside the system.
