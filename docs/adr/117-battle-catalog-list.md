# 117 battle-catalog-list
epic: none · pr: none

## Decisions
- @battle @scope — The battle catalog is one list page whose top row selects exactly one entity type (enemy, assistant, event sinner), and each type keeps its own facets and search query in its own module-scope filter store beside a scalar `entityType` store. Stage cases overlap (217 enemy files are engaged by both story and Mirror Dungeon), so only the entity type partitions the catalog without showing one entity under two tabs. REJECTED: stage type as the top-level category with entity type as a facet — an enemy in two cases appears under two tabs, and the entity facet has a single value on every tab but Story, because assistants and event sinners are almost all story-only. REJECTED: the entity type as one more facet in the shared store — `resetAll` would send the page back to the default type and the active-filter count would count the tab. REJECTED: the entity type in the URL — ADR 100 keeps list state out of the URL, and the detail routes already carry the type in their path.
- @battle @reset — Reset clears the selected type's facets and query and leaves the type and the other types' filters untouched; switching type restores the filters last set on that type. This is ADR 100's list → detail → back guarantee applied one level up.
- @battle @card (taste) — One card per shipped enemy file, labeled by name under a sprite in a declared card geometry whose longer side is 256 px. 1,415 of the 1,657 spawn-capable enemies share their name and sprite with another file, and the rule for merging them is not yet chosen; the decision holds until a grouping key over name and sprite is adopted. REJECTED: grouping by name and sprite now — same-named files differ in stats and in 203 groups in skill sets, and the grouping key has to be judged against the shipped list.
- @battle @facets — Enemies filter by stage case (story, Mirror Dungeon, Refraction Railway, Refractral, Luxcavation) with a per-case drill-down (chapter, theme pack or event, line, none, dungeon), plus name search; assistants and event sinners filter by name only. Luxcavation is a case because 133 of the 135 enemies it engages appear nowhere else. REJECTED: Luxcavation under Story — its stages carry a chapter only because the pipeline attached the chapter that unlocks them.
- @battle @inclusion — An entity with no engagement is not listed; the pipeline excludes it from the spec list, and a Mirror Dungeon engagement that resolves to no theme pack, hidden pool or event is dropped before that test. REJECTED: a fifth "unused" bucket — 171 orphans, 22 of them named "?", that no stage in the client spawns.
- @battle @slice — The catalog is one `battle` slice holding one entity section per family, and the entity-section guard discovers sections one directory deeper, naming them `battle/<family>`. The type row lives on one page, and a page may not import another page's list. REJECTED: one slice per family — the page holding the type row would import three slices, or the row would become three routes, which @scope rejects. REJECTED: one section spanning three families — three spec lists with different facets behind one entity type.

## Takeaway
- takeaway: when two candidate axes both look like categories, the one whose values partition the items is the tab and the one whose values overlap is a filter; picking the overlapping axis turns every multi-valued item into a duplicate card.
