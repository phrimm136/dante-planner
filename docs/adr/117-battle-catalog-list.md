# 117 battle-catalog-list
epic: none · pr: none

## Decisions
- @battle @scope — The battle catalog is one list page whose top row selects exactly one stage mode (Story, Luxcavation, Mirror Dungeon, Refraction Railway, Refractral), and within it one entity type (enemy, assist unit, event sinner); both follow the filter template's single-select controls, and a type with no entity in the mode shows the empty-result state. An entity engaged by two modes appears under both, as intended: its composition differs by mode. REJECTED: entity type as the top row with modes as a facet — the reader browses by where they fight, and the per-mode duplicate is the per-mode kit. REJECTED: the selection in the URL — ADR 100 keeps list state out of the URL.
- @battle @order — Within a mode, cards follow the mode's in-game order from the spec list's per-case sort key: Story by canto, then Intervallo, then Walpurgis Night, each by chapter and node; Mirror Dungeon by theme pack id, then node id; Railway by line and node. REJECTED: id order — ids encode release batches, not where a player meets the entity.
- @battle @sprite — A card draws its sprite at one pixels-per-unit (53 px per world unit) with the skill-slot anchor 15 % below the card top, cropping what falls outside, so relative sizes match the battle screen. REJECTED: fitting each sprite to the card — small units look large and bosses tiny.
- @battle @reset — Reset clears the filters and query and leaves the mode and type selection untouched.
- @battle @card — One card per origin group (static ADR 389), labeled by the group's name, or its per-mode name where the mode's copy is named differently, under its sprite in a declared card geometry whose longer side is 256 px. REJECTED: one card per shipped unit file — the client's per-mode copies showed one enemy up to nine times.
- @battle @facets — Enemies filter by stage case (story, Mirror Dungeon, Refraction Railway, Refractral, Luxcavation) with a per-case drill-down (chapter, theme pack or event, line, none, dungeon), plus name search; assistants and event sinners filter by name only. Luxcavation is a case because 133 of the 135 enemies it engages appear nowhere else. REJECTED: Luxcavation under Story — its stages carry a chapter only because the pipeline attached the chapter that unlocks them.
- @battle @inclusion — An entity with no engagement is not listed; the pipeline excludes it from the spec list, and a Mirror Dungeon engagement that resolves to no theme pack, hidden pool or event is dropped before that test. REJECTED: a fifth "unused" bucket — 171 orphans, 22 of them named "?", that no stage in the client spawns.
- @battle @slice — The catalog is one `battle` slice holding one entity section per family, and the entity-section guard discovers sections one directory deeper, naming them `battle/<family>`. The type row lives on one page, and a page may not import another page's list. REJECTED: one slice per family — the page holding the type row would import three slices, or the row would become three routes, which @scope rejects. REJECTED: one section spanning three families — three spec lists with different facets behind one entity type.

## Takeaway
- takeaway: browse by where the player fights; a thing that appears in two places appears in both lists, and the copy each place fields is what that list shows.
