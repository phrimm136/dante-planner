# 576 optional-lives-only-on-the-line-that-receives-it
epic: none · pr: none · supersedes: 061 @convention @nullability

## Decisions
- @convention @nullability — `java.util.Optional` appears only where a repository or a library hands it over, and the line that receives it turns it into a type: a lookup that can miss returns the shared sealed `Option` (`Some` or `None`), a domain sealed type only when absence has more than one meaning or carries data, and, when every caller refuses a miss the same way, it refuses on that line and returns the found value. The parts of the earlier rule that still hold: a declaration may be nullable only where null is data at a wire boundary, mapped to explicit types immediately on both sides, and internal null-as-data (a nullable column encoding a third state) is a migration target; a provably present value is primitive or non-null; `java.util.Optional` never appears on fields, components or parameters; callers never write null literals, because a delegating overload or a named factory spells the absent case at the definition; boundary boxes remain where Bean Validation needs the box to detect absence. Callers of one `Optional` lookup each re-decided what its absence meant, with `isPresent` and `get`, `map` and `orElseGet`, or `orElseThrow`.
  REJECTED: `java.util.Optional` past the receiving line — it is not sealed, `get` and `orElse(null)` reopen null, and `ofNullable` admits null; `Option` has no `get`, nothing in it returns null, and `Some` refuses null.
  REJECTED: one domain type per lookup by default — a type whose two cases are found and missing names nothing `Option` does not, and its callers repeat the same switch.
  REJECTED: sentinel values in place of absence — a sentinel is a lie the type system repeats.
  INVARIANT: in the modules the rule's scope set names, no method returns or takes `java.util.Optional` and no field holds one, inside a generic too, outside repository packages — `OptionalSignatureScopeRuleTest`.
  NON-GOAL: modules outside the scope set — a module joins by widening the scope set, never through a list of exempt sites, because a list of sites is read as a pattern to copy.
  NON-GOAL: repository signatures — Spring Data hands back `Optional`, and `Option.from` converts it on the caller's receiving line.
- @convention @decision-purity — A method whose return type is a sealed type marked `@ReadResult`, `Option` among them, may reach repository and JDBC reads and nothing else: a repository query method that Spring Data runs as a read (a derived query whose subject is `find`, `read`, `get`, `query`, `search`, `stream`, `count` or `exists`, or a `@Query`), with neither `@Modifying` nor `@Lock` and no `FOR UPDATE`, `FOR SHARE` or `LOCK IN SHARE MODE` in its query, a `JdbcTemplate` query, and the `ResultSet` reads under it; a default method, or a method a repository fragment declares and its implementation defines, is walked like any other code; every other method returning a sealed type or an enum stays a pure decision. A lookup that returns `Option` or a case type reads the database by definition, and the decision rule refused any sealed return that reached a port.
  REJECTED: naming the lookup's type `...Outcome` — an outcome reports what a command did, and a lookup does nothing.
  REJECTED: wrapping the result in a non-sealed carrier — the carrier exists only to pass the rule.
  REJECTED: `@Parsed` — a `@Parsed` type is built only by its own factory and is never an interface, while a lookup builds the cases of a sealed interface.
  INVARIANT: a `@ReadResult` lookup that also writes, takes a row lock through a repository query, logs, reads the clock, touches Redis or publishes an event is named, a `find`-named default method, fragment method or locking query included, and so is an unmarked sealed return that reads a repository — `DecisionPurityTest`.
  NON-GOAL: the SQL text a lookup passes to `JdbcTemplate` — a locking clause there is the reviewer's to see; reading SQL constants out of bytecode is brittle and covers only literals.
- @convention @decryption — Decrypting with a given key and IV is pure: `Cipher.getInstance`, `Cipher.init` with an explicit parameter spec, `Cipher.doFinal`, the key and GCM spec constructors and `AEADBadTagException` construction count as computation, while `SecureRandom` and a `Cipher.init` that draws its own IV stay effects. The OAuth state check decrypts its cookie and answers opened, missing or rejected with a reason, three meanings `Option` cannot hold; with decryption counted as an effect its only honest form was a thrown and caught rejection.
  REJECTED: treating all of `javax.crypto` as pure — encryption draws randomness for its IV.
  REJECTED: throwing the rejection and catching it in the controller — the rejection is an expected answer the check can return.
  INVARIANT: a decision that only decrypts passes, and one that draws randomness or lets the cipher draw its IV is named — `DecisionPurityTest`.

## Takeaway
- takeaway: an absent value means something different to each caller; give it one sealed shape where it is received, and a domain name only when absence means more than one thing.
