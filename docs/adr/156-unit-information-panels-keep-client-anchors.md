# 156 unit-information-panels-keep-client-anchors
epic: none · pr: none · supersedes: 149 @separators

## Decisions
- @skill @passive @sanity @layout — Every element of the skill, passive and sanity panels keeps the client's anchor edge (left, right, stretch or centre) and its fixed offset in client units from that edge, on battle, identity and E.G.O pages alike; the card keeps a fluid width and line wrapping is not matched. The client panel is 1304.2 units wide at every screen size, so an element's offset from its anchor edge is the one placement fact that survives a different card width. REJECTED: a card fixed at 1304.2 units — desktop pages would show 456-pixel cards; REJECTED: offsets as fractions of the card width — they agree with the client at one width only.
  INVARIANT: no panel length derives from the card width, and fixed-offset elements measure the same at 390 and 1440 pixels — layout table tests and a browser check.
  NON-GOAL: the Japanese text-bounds height, the E.G.O requirement narrowing and runtime-only rows (panic type-change buff, lock overlays).
- @skill @passive @sanity @stacking — Where a right-anchored decoration (importance triangle, caution bands, lock icons, sanity condition icons) overlaps left-anchored content, the content draws above it, as the client's sibling order draws it. REJECTED: document order — a condition icon painted over its own text.
  INVARIANT: right-anchored decorations sit below content — stacking class tests and browser hit tests.
- @skill @passive @sanity @fit — Names and tags the client auto-sizes (skill and passive names, panic name, condition tags) are fitted by the card-name fit function over the game's own glyph advances, with the client node's size range, box, margins and spacing. The client shrinks such text between its minimum and maximum size before it wraps a line the box cannot hold, so a fixed size wrapped names the game draws on one line. REJECTED: precomputing a size per name in the pipeline — the fit function already reproduces the client's rule for any string, and a table would need regenerating whenever a name changes.
- @skill @separators — A 5-unit line with 30 units on each side separates every pair of skill boxes, on every page; section titles sit directly on their content without a rule. The client's skill tab draws the line after every box but the last. REJECTED: lines only between the client's skill groups — the client draws no group boundary of its own.
- @skill @passive @sanity @typography — Panel text takes the client's typography: font sizes, the first line's height and each block's line pitch from the font's face metrics and `lineSpacing`, character and word spacing, and colours. Component gaps in the client come out of those text metrics — our 20-pixel line alone put a two-line description and its coin rows 41 units lower than in-game. REJECTED: keeping the page's line pitch, spacing and colours — the gaps between components could not match while the text blocks between them had other heights.

## Superseded
- @skill @passive @nameplate → 193 — Skill and passive names are one name-plate component sharing the passive plate's shape (72.74 units tall, the passive tail), each placed at its own panel's anchor, while the name inside follows its own client node: a skill name auto-sizes 0–45 in a 60-unit box with margins 20/50 and sits on its midline, a passive name 25–40 with margins 30/100; each carries its node's underlay. In-game the two plates read as the same element, but a skill name set in the passive node's 40-unit range measured smaller than the capture (name-to-description glyph ratio 1.17, which 45 gives and 40 does not). REJECTED: one text node for both — the skill names came out a size too small; REJECTED: transcribing each plate separately — two plates for what the reader sees as one element.
- @battle @separators → 156 — Skill lists draw a separator only between the client's own groups: identity skill 1/2/3/defense and E.G.O awakening/erosion; battle skills have none. Section titles sit directly on their content without a rule. REJECTED: one rule per section title — a line between a title and its own content separates nothing.

## Takeaway
- takeaway: when the page's container cannot match the client's, keep what the client fixes relative to each element's own anchor.
