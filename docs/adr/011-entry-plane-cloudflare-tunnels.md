# 011 entry-plane-cloudflare-tunnels
epic: none · pr: none

## Decisions
- @edge @tunnels @steering — Two named tunnels, one per region, behind a single Cloudflare load balancer with traffic steering. REJECTED: one tunnel with cross-region replicas — a routing heuristic that cannot name the regions cannot health-check, weigh, or drain them individually, which leaves it blind to the most common failure class: a region serving errors while its transport stays happily connected. The vendor's own availability documentation disclaims steering guarantees for replicas.
- @edge @terraform — Every Cloudflare object (tunnels, tunnel configuration, load balancer, pools, monitors, DNS) is managed by the Cloudflare Terraform provider in its own root module. REJECTED: dashboard-maintained objects — when the serving path crosses a vendor control plane, hand-maintained artifacts drift and are invisible to review.
- @edge @drain @latency — The soft-failure drain window widens from roughly 30 seconds to roughly one to three minutes, floored by the load-balancer monitor interval. Accepted for this service's stakes, priced into the choice rather than discovered afterwards.
- @edge @mtls @origin-auth — Authenticated origin pull and the origin client-certificate artifacts are removed rather than migrated. REJECTED: carrying mTLS forward — the permissive client-certificate mode admitted certless callers by design, forced by a certless health prober, so it never gated anything it was believed to gate; the tunnel credential is strictly stronger origin authentication.
- @edge @affinity — Load-balancer session affinity is classified nice-to-have rather than an invariant, because read-your-writes is already guaranteed at the application seam. REJECTED: treating affinity as a correctness mechanism — it would make a routing convenience load-bearing for consistency.
- @edge @rollback — A dormant rollback path is time-boxed to one full deploy cycle plus the drill set, then destroyed. REJECTED: indefinite dormancy — unowned standby infrastructure silently defeats a cost-driven migration, and the resources it holds may be unrecoverable once released.
- @edge @traefik — The in-cluster ingress is retained as a plain pass-through, since the node it runs on is kept for a future routing seam regardless, making its marginal cost one sub-millisecond hop and some manifest upkeep. REJECTED: pointing the tunnel straight at the backend service — technically leaner, but it discards the routing seam and the ability to run the stack without the edge provider in local development.
- @edge @egress @cost — Node public addressing remains the egress path; the tunnel closes inbound only. REJECTED: NAT gateways with private subnets — the absence of NAT is a deliberate cost decision, not an oversight to be corrected.
- @edge @writes — Writes from the secondary region travel cross-region to the primary on the ordinary application path. REJECTED: forwarding writes at the edge by HTTP method — it needs a second cross-region trust surface, a split of the consistency filter, and special routing for the mutating OAuth callback, all to save about a second on an action that is rare and explicitly user-initiated.

## Takeaway
- takeaway: a security control that admits the caller it was supposed to reject is not defense in depth, it is a comment. The permissive-mode origin check was cited in three places as "the real gate" while structurally gating nothing, which is what a control nobody has tried to defeat looks like from the inside.
