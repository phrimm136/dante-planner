# 158 text-measure-follows-the-tmp-pen
epic: none · pr: none · supersedes: 104 @cards @text (letter spacing)

## Decisions
- @cards @text — A line's width is its glyph advances plus the character spacing, the face's own spacing offset and the word spacing charged between code points, not after the last one; the offset is read per face from the shipped advance tables. TextMeshPro's width test adds the last glyph's advance to a pen that has moved by the spacing only after each earlier glyph, and the EN face (Mikodacs) carries a +0.06 em offset on every glyph. Under this rule 432 of 435 panic names fit as the client's auto-size does, against 336 under ADR 104's rule, and EN identity, E.G.O and start-buff names break where the game breaks them. REJECTED: charging spacing after every code point — the client's width test does not, and names came out a hundredth of an em too wide; REJECTED: a face offset written in the page — the value belongs to the font asset and differs per face in the fallback chain.
  INVARIANT: one measure serves every TextMeshPro node the page reproduces (card names, name plates, panic names, tags) — fontAdvances and textNode tests.
- @cards @text @height — A fitted block's height is the first line's tallest ascender, then for each further line the deepest descender above it plus that line's tallest ascender plus the display face's line gap plus the node's line spacing, then the last line's deepest descender; each glyph brings the ascender and descender of the face that drew it, fallback included, while the line gap is always the display face's (`lineHeight - ascender - descender`). TextMeshPro 3.2, which the client ships, reads the gap once from the node's own font asset and drops each line by `-m_maxLineDescender + ascender + lineGap * baseScale + m_lineSpacing * currentEmScale` (https://github.com/needle-mirror/com.unity.textmeshpro/blob/3.2.0-pre.10/Scripts/Runtime/TextMeshProUGUI.cs L2495, L2577, L3513, L3522). In game, 21008 breaks as "오혈읍루 [汚血" / "泣淚]" and 20809 stands on one line; this rule yields both, and a line of the display face alone keeps its face line height as before. REJECTED: the fallback face's line gap — it also yields both breaks, but TextMeshPro never reads a fallback's gap; REJECTED: each line's tallest face line height plus the line spacing (the previous rule) — a KOTRA line carrying a Noto hanja pitches 1.28 em instead of 1.48, and 21008 breaks at "[汚".
  INVARIANT: every fitted node's height test goes through `linePitch` over `lineMetrics` — fitText and fontAdvances tests.

## Takeaway
- takeaway: measure text the way the engine's line breaker measures it, not the way its pen draws it.
