## Phase Summary

Ten sequential phases implementing docs/tasks/031-fe-structure-refactor/requirements.md: hygiene → build shared primitives → adopt them (data layer, then components) → fix type direction → relocate files into the four-layer model (components kit, shared concepts, codemod splits) → freeze boundaries → sync docs.

Cross-cutting rules for EVERY phase:
- Full FE gate after each phase: `yarn --cwd frontend tsc -b > /tmp/fe-typecheck-<session-id>-<phase>.log 2>&1` and `yarn --cwd frontend vitest run > /tmp/fe-test-<session-id>-<phase>.log 2>&1` (append `&& echo PASS >> … || echo FAIL >> …`). Both must be green before the phase is marked done. Bare `vitest`/`tsc` at repo root is hook-blocked — always `--cwd frontend`.
- Behavior-preserving: no logic changes during moves; no `as any` ever; divergent behavior found in duplicated code is PRESERVED and flagged, not "fixed" (e.g. EgoGiftSearchDropdown intentionally lacks the sinner-name append its siblings have — keep it).
- Moves use `git mv` (staging renames is expected); agents NEVER `git commit` — the user commits manually.
- Barrels use named re-exports (`export { x } from './x'`), never `export *` — the Tiptap-out-of-entry-chunk bundle invariant depends on tree-shakeable form.
- FE test files are excluded from every tsconfig (known project quirk): anything that must be TYPECHECKED as a gate (the planner drift guard) must live under `src/` proper, NOT in `__tests__/`. Harness LSP may show false 2307/2339 on test files — trust `tsc -b` + vitest.
- Before moving any file flagged "reverse-grep", run REVERSE import tracing (grep all of src for who imports it) — forward tracing misses dual-consumers (historical misses: CommunityPlansErrorFallback, BanDialog). A 2+-domain consumer changes the destination per the ownership rule in the spec.
